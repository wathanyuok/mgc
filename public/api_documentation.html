Overview

polymorphic — 9 facility tables (Loan · PN · FP · OD · TR · LG · LC · Lease · FXF)

Concept

แยกบทบาท Maker (ผู้ตั้งเรื่อง) กับ Approver (ผู้อนุมัติ) — เอกสารทุกฉบับต้องผ่านสายตาบุคคลที่ 2 ก่อนขึ้นสถานะ Active

LifecycleDraft → Ready for Approval → Active (หรือกลับสู่ Draft พร้อมเหตุผลเมื่อ Approver ขอให้แก้ไข)
Columns per tablesubmitted_by · submitted_at · approved_by · approved_at · rejection_reason
PermissionSubmit ใช้สิทธิ์ edit · Approve/Request Changes ใช้สิทธิ์ approve

src/lib/bank-statement/match-by-bank-ref.ts

Overview

Client-side function ที่วิ่งทันทีหลัง Save · อ่านคำอธิบายรายการเดินบัญชี (description) ในแต่ละแถว → หารูปแบบ MCL หรือเช็คเลขที่ → ค้นในตารางสัญญาที่เกี่ยวข้อง → ถ้าเจอ 1 รายการ update facility_type + facility_id + source_period ในแถว

Tier 1a — MCL (Contract Reference)

PatternMCL <11-digit> <5-digit> (contract_ref + period_no)
Search columnspn_number, lg_no, account_no (OD), tr_no, fxf_no, lc_no, bank_ref (loans/floor_plans/leases — Migration 0062)
FunctionextractMCL(description) · matchByBankRef(lines)

Tier 1b — Cheque Number

Patternเช็คเลขที่ <n>
Search columnap_cheque_requests.cheque_no
Resolutionเมื่อเจอ cheque → ใช้ source_type (REPAYMENT / LEASE_PAYMENT / LOAN_INTEREST) เพื่อ resolve กลับไปยัง facility ต้นทาง
FunctionextractChequeNo(description) · matchByChequeNo(lines)

Rules

PriorityMCL ก่อน → Cheque หลัง · ห้ามใช้พร้อมกัน
Preservationห้ามทับ facility_id ที่ผู้ใช้เลือกเอง — ข้ามแถวที่มีค่าอยู่แล้ว
TrimWhitespace-trim ref ทั้งสองฝั่งก่อน compare
Match Algorithm (pseudo)
for line in statement_lines:
    if line.facility_id: continue  # ห้ามทับ

    mcl = extractMCL(line.description)
    if mcl:
        for tbl in ALL_9_FACILITY_TABLES:
            row = tbl.find(bank_ref = mcl.contract_ref.trim())
            if row:
                line.facility_type = tbl.type
                line.facility_id = row.id
                line.source_period = mcl.period_no
                break
        continue

    chq = extractChequeNo(line.description)
    if chq:
        req = ap_cheque_requests.find(cheque_no = chq)
        if req:
            line.facility_type = req.source_type
            line.facility_id = req.source_id

NetSuite AP Callback Webhook

POSTwebhook_ap_status 🔌 (Proposed — Wave 2)

{{api_host}}/webhook/ap-status

Overview

Inbound webhook — NetSuite AP เรียกเมื่อสถานะ Vendor Bill เปลี่ยน (Pending → Issued → Cleared → Cancelled) · ระบบตัวรับตรวจ HMAC-SHA256 signature → match ด้วย netsuite_ap_id → update ap_cheque_requests

สถานะปัจจุบัน: Structure เป็น Mock (task #48) · spec นี้เตรียมไว้ให้ทีม NetSuite ของ MGC IT พัฒนาฝั่ง outbound

Request — Headers

Content-Typeapplication/json
X-SignatureHMAC-SHA256 hex digest ของ body + shared secret

Request — Body

FieldTypeMandatoryDescription
external_idStringYESID ที่ระบบ Lease & Loan เป็นคนกำหนดตอนส่ง Vendor Bill ออก (เช่น MGC-{loan_no}-P{period_no})
netsuite_ap_idStringYESAP Bill ID จาก NetSuite — primary match key
statusEnumYESPending / Issued / Cleared / Cancelled
cheque_noStringNOเลขที่เช็ค (มีเมื่อ status=Issued ขึ้นไป)
issued_dateDateNOวันที่ออกเช็ค (ISO 8601)
cleared_dateDateNOวันที่เคลียร์เช็ค (ISO 8601)

Response

FieldTypeDescription
ackBooleantrue = รับและอัปเดตสำเร็จ
ap_cheque_request_idString (UUID)UUID ของ ap_cheque_requests row ที่ถูก update

Status codes

200สำเร็จ · อัปเดตเรียบร้อย
200 (idempotent)รับซ้ำด้วย netsuite_ap_id + สถานะเดิม → คืน ack เหมือนเดิม ไม่ทำงานซ้ำ
401X-Signature ไม่ถูกต้อง หรือขาด
404ไม่พบ ap_cheque_requests ที่มี netsuite_ap_id ตรงกัน

Business Rules

Idempotentรับซ้ำได้ — netsuite_ap_id + status เดิม → ตอบเหมือนเดิม (BR-SYS-010)
HMAC verifyตรวจลายเซ็นก่อนทุกครั้ง · shared secret เก็บใน env var (BR-SYS-011)
Audit logบันทึกทุก request ที่เข้ามา (payload + response + timestamp) ในตาราง webhook_log (BR-SYS-012)
